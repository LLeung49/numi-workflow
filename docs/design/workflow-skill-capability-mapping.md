# 1. 文档目的

`workflow-skill-capability-mapping.md` 用于回答：

> 当前 numi-workflow 的 Skill
> 分别承担哪些能力？哪些职责已经合理归属？哪些职责未来需要迁移、拆分或交给外部执行能力？

它连接：

    能力模型

        ↓

    numi Skill 架构

        ↓

    未来 Workflow 演进

该文档不是定义能力本身，而是评审当前 Skill 是否符合能力边界。

------------------------------------------------------------------------

------------------------------------------------------------------------

## 可借鉴方向

参考：

-   Matt domain-modeling

未来增强：

  能力                   方向
  ---------------------- -------
  领域术语沉淀           Adapt
  自动识别重要长期知识   Adapt

# 9. 当前主要架构调整方向

## 9.1 feature-slice 与 feature-deliver 分离

当前：

    feature-slice
    =
    任务设计
    +
    部分执行准备

未来：

    feature-slice
    =
    任务设计


    feature-deliver
    =
    任务运行管理

------------------------------------------------------------------------

## 9.2 Skill 不应该成为能力孤岛

未来：

    Skill

    不是独立工具

    而是能力生命周期中的一个节点

------------------------------------------------------------------------

## 9.3 外部 Skill 作为执行后端

未来：

    numi workflow

            ↓

    能力契约

            ↓

    外部执行 Skill

# 10. v0.7 后续优化计划

## project-discovery

方向：

-   引入更强领域建模；
-   减少模板化产物；
-   强化项目基线质量。

------------------------------------------------------------------------

## feature-shape

方向：

-   自适应设计深度；
-   更明确事实与决策边界；
-   减少不必要用户确认。

------------------------------------------------------------------------

## feature-slice

方向：

-   聚焦任务图生成；
-   删除运行时职责；
-   强化交付接口。

------------------------------------------------------------------------

## feature-deliver

方向：

-   建立执行后端模型；
-   管理长期 Agent 交付循环；
-   建立证据驱动交付。

------------------------------------------------------------------------

# 11. 总结

numi Skill 架构的目标不是覆盖所有软件开发活动。

而是：

> 用最小的核心能力连接人的目标、项目基线、Agent 执行能力和最终可信交付。

未来：

-   执行能力越来越外部化；
-   治理能力越来越重要；
-   Skill 越来越像生命周期中的能力节点。
