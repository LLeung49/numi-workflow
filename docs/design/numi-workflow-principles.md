# Numi Workflow 原则（Numi Workflow Principles）

-   版本：v0.7-draft
-   状态：设计基线
-   文档类型：长期项目原则
-   目标：定义 numi-workflow 的核心使命、边界和长期演进方向。

------------------------------------------------------------------------

# 1. 核心使命（Mission）

## 1.1 Numi Workflow 的定位

> numi-workflow 不负责替代 coding agent，而是帮助人类将复杂目标转化为
> Agent 可以可靠完成的工作单元，并在人和 Agent
> 长周期协作过程中保持目标、上下文和决策的一致性。

随着 AI Agent、Harness
和基础模型能力不断提升，软件开发的核心挑战正在从：

> Agent 是否具备足够的编码能力

逐渐转变为：

> 人类是否能够有效地定义目标、传递意图、管理上下文，并与 Agent
> 建立高质量协作关系。

Numi Workflow 的目标不是降低人类参与，而是提升人类与 Agent 的协同效率。

------------------------------------------------------------------------

# 2. 长期愿景（Vision）

Numi Workflow 希望帮助用户逐步建立：

## Human-Agent Collaboration Capability

即：

> 人类理解如何与 Agent 协作，Agent
> 理解如何服务人类目标，双方能力共同成长。

未来高质量的软件开发不是：

    Human
      |
      | 下指令
      v
    Agent
      |
      | 生成代码
      v
    Software

而应该是：

    Human

      ↓

    目标定义
    领域判断
    价值取舍
    风险控制

      ↓

    Agent

      ↓

    分析
    设计
    实现
    验证

      ↓

    共同完成目标

------------------------------------------------------------------------

# 3. 核心理念：协同进化（Co-evolution）

Numi Workflow 认为：

未来人与 Agent 的关系不是简单的：

    Human 使用 Agent

而是：

    Human + Agent 协同进化

随着：

-   基础模型能力提升；
-   Agent Harness 能力提升；
-   用户自身 AI 协作能力提升；
-   项目复杂度变化；

协作方式也应该动态调整。

------------------------------------------------------------------------

# 4. 自适应协作原则（Adaptive Collaboration）

Numi Workflow 不追求固定流程。

相反，应根据：

-   Agent 能力；
-   用户能力；
-   项目阶段；
-   任务复杂度；
-   风险等级；

调整协作模式。

例如：

## 简单任务

可以：

-   减少人工确认；
-   增加 Agent 自主执行。

------------------------------------------------------------------------

## 高风险任务

需要：

-   更严格的功能定义；
-   更明确的决策记录；
-   更充分的验证。

------------------------------------------------------------------------

## 用户能力提升后

Workflow 应帮助用户：

-   提高目标表达能力；
-   提高任务拆解能力；
-   提高 Agent 协作能力。

------------------------------------------------------------------------

# 5. Numi 解决的问题

当前 Agent Coding 的主要瓶颈不是：

-   不会生成代码；
-   不会执行命令；
-   不会调用工具。

而是：

## 5.1 意图转换问题

人类拥有：

-   业务目标；
-   领域知识；
-   隐含经验。

Agent 需要：

-   明确目标；
-   可执行约束；
-   验收标准。

Numi 负责减少：

    Human Intent

            ↓

    Agent Understanding

    之间的信息损失。

------------------------------------------------------------------------

## 5.2 长周期协作问题

复杂项目不是一次对话完成。

需要保持：

-   项目背景；
-   历史决策；
-   当前状态；
-   未完成事项。

------------------------------------------------------------------------

## 5.3 决策一致性问题

Agent 可以快速生成方案。

但长期项目需要：

-   为什么这样设计；
-   为什么拒绝其它方案；
-   哪些约束不能改变。

------------------------------------------------------------------------

# 6. Numi 的能力边界

## Numi 负责

### 项目理解

建立：

-   项目基线；
-   长期项目依据；
-   领域上下文。

对应：

`project-discovery`

------------------------------------------------------------------------

### 功能定义

帮助：

-   明确目标；
-   澄清边界；
-   管理决策。

对应：

`feature-shape`

------------------------------------------------------------------------

### 工作单元设计

帮助：

-   拆解任务；
-   定义验收；
-   建立执行契约。

对应：

`feature-slice`

------------------------------------------------------------------------

## Numi 不负责

### 不替代 Coding Agent

不竞争：

-   Codex；
-   Claude Code；
-   其它 Coding Agent。

------------------------------------------------------------------------

### 不重复成熟工程能力

优先复用：

-   Superpowers；
-   Matt Pocock Skills；
-   TDD；
-   Code Review；
-   Debug Workflow。

------------------------------------------------------------------------

### 不成为固定 Workflow Engine

Numi 不追求：

-   固定流程；
-   强制步骤；
-   所有任务使用同一模式。

------------------------------------------------------------------------

# 7. 与生态能力的关系

## Coding Agent

负责：

-   编码；
-   调试；
-   执行。

------------------------------------------------------------------------

## Agent Harness

负责：

-   工具调用；
-   任务循环；
-   环境管理。

------------------------------------------------------------------------

## Workflow Framework

提供：

-   通用执行模式。

------------------------------------------------------------------------

## Numi Workflow

负责：

> 人类目标与 Agent 执行之间的协作协议。

------------------------------------------------------------------------

# 8. 持续学习原则

Numi Workflow 本身也是一个学习系统。

它应该随着：

-   用户实践；
-   Agent 能力变化；
-   社区最佳实践；
-   工程经验积累；

持续演进。

新增能力必须回答：

1.  这个问题是否来自真实协作痛点？
2.  是否提升 Human-Agent Collaboration？
3.  是否已有成熟方案可以复用？
4.  是否会增加不必要复杂度？

------------------------------------------------------------------------

# 9. North Star

Numi Workflow 的最终目标：

> 让人类和 Agent
> 发挥各自优势，弥补彼此不足，通过持续学习和协作能力提升，以更高效率、更高质量地完成复杂目标。

------------------------------------------------------------------------

# 10. 设计约束

未来所有 numi 能力设计都应遵循：

## 优先复用

不要重复造已有能力。

------------------------------------------------------------------------

## 保持简单

不要为了未来可能性提前构建复杂系统。

------------------------------------------------------------------------

## 面向协作

优先解决：

人与 Agent 如何更好合作。

------------------------------------------------------------------------

## 渐进演进

通过真实项目验证，再固化稳定模式。
