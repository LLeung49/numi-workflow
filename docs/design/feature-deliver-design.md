# 功能交付设计（Feature Deliver Design）

-   版本：v0.7-revision
-   状态：设计评审中
-   目标：定义 numi 如何管理已批准 Feature 的交付生命周期。
-   范围原则：v0.7 聚焦最小可用交付闭环，不提前建设完整 Agent Runtime。

------------------------------------------------------------------------

# 1. 定位

feature-deliver 负责：

> 将已经通过功能规格评审和任务拆解评审的
> Feature，转化为可追踪、可验证、可恢复的交付过程。

feature-deliver 不负责重新定义需求，也不替代成熟执行能力。

------------------------------------------------------------------------

# 2. 与前序 Skill 的边界

## feature-shape

回答：

> 为什么做？做什么？边界是什么？

输出：

-   功能规格；
-   决策记录；
-   未决事项收敛结果；
-   验收条件。

------------------------------------------------------------------------

## feature-slice

回答：

> 需要完成哪些开发任务？

输出：

-   开发任务；
-   依赖关系；
-   任务验收条件；
-   实施上下文。

------------------------------------------------------------------------

## feature-deliver

回答：

> 当前如何可靠完成这些任务？

负责：

-   交付状态；
-   执行推进；
-   证据收集；
-   阻塞处理。

------------------------------------------------------------------------

# 3. v0.7 范围

## Included（本版本实现）

### 3.1 Delivery State

维护 Feature 当前交付状态。

示例：

``` yaml
feature:
  status: delivering

tickets:
  TICKET-01:
    status: completed

  TICKET-02:
    status: blocked
```

状态至少包括：

-   ready；
-   delivering；
-   blocked；
-   completed。

------------------------------------------------------------------------

### 3.2 Frontier Management

计算当前可执行任务。

输入：

-   tasks.md；
-   任务依赖；
-   当前状态。

输出：

-   下一批可执行任务。

原则：

> 只推进满足依赖和约束的任务，不自行扩大范围。

------------------------------------------------------------------------

### 3.3 Evidence Collection

完成状态必须有证据支持。

证据包括：

-   代码变更；
-   测试结果；
-   命令输出；
-   Review 结果；
-   生成工作产物。

原则：

> Agent 声明完成不等于交付完成。

------------------------------------------------------------------------

### 3.4 Handoff Support

支持长程 Agent 工作中的上下文切换。

场景：

-   Token 接近限制；
-   Session 中断；
-   Agent 更换。

保存：

-   当前任务状态；
-   已完成内容；
-   未完成内容；
-   下一步动作；
-   必要上下文。

------------------------------------------------------------------------

# 4. v0.7 不实现范围

以下能力暂不进入实现：

## Agent 自动调度

不实现：

-   自动选择 Codex；
-   自动选择 Claude Code；
-   自动组合多个 Agent。

原因：

执行后端仍处于快速变化阶段。

------------------------------------------------------------------------

## Capability 自动发现

Capability Registry 当前作为设计基础。

v0.7 不实现：

-   自动扫描环境；
-   自动注册 Provider；
-   动态能力市场。

------------------------------------------------------------------------

## Adaptive Autonomy

目标保留。

但需要真实运行数据支持。

未来根据：

-   项目阶段；
-   用户能力；
-   Agent 能力；

动态调整自主程度。

------------------------------------------------------------------------

# 5. 核心模型

## Task Model

描述：

> 应该做什么。

来源：

feature-slice。

特点：

静态。

------------------------------------------------------------------------

## Delivery Model

描述：

> 当前做到哪里。

来源：

feature-deliver。

特点：

动态。

------------------------------------------------------------------------

## Evidence Model

描述：

> 为什么认为完成。

来源：

执行过程。

------------------------------------------------------------------------

三者关系：

    Task Model

        ↓

    Delivery Model

        ↓

    Evidence Model

------------------------------------------------------------------------

# 6. 执行后端关系

# 9. 设计原则总结

feature-deliver 的核心不是：

> 让 numi 自己完成所有开发。

而是：

> 让不同执行能力围绕同一个项目目标可靠协作。

numi 保持：

-   项目基线；
-   决策边界；
-   交付状态；
-   证据可信度。

外部 Agent 提供：

-   编码；
-   测试；
-   调试；
-   工程执行。
