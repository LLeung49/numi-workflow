# Numi Workflow v0.7 架构重构（Architecture Reset）

-   版本：v0.7
-   状态：设计基线
-   文档类型：架构决策文档
-   目标：明确 numi-workflow
    的长期定位、能力边界和演进方向，避免演化为新的 Agent Runtime。

------------------------------------------------------------------------

# 1. 为什么需要架构重构

numi-workflow 在早期探索过程中逐渐增加了：

-   Workflow 生命周期管理；
-   Capability Registry；
-   Feature Delivery；
-   Agent 协同；
-   Handoff 支持。

这些方向部分来自真实痛点，但也存在一个风险：

> numi-workflow 可能逐渐从"帮助人类与 Agent 协作"，演变成"重新构建一个
> Coding Agent Harness"。

因此 v0.7 需要重新确认：

-   numi 应该解决什么问题；
-   numi 不应该解决什么问题；
-   哪些能力应该复用生态已有方案。

------------------------------------------------------------------------

# 2. Numi Workflow 的核心定位

## Mission

> numi-workflow 不负责替代 coding agent，而是帮助人类将复杂目标转化为
> Agent 可以可靠完成的工作单元，并在人和 Agent
> 长周期协作过程中保持目标、上下文和决策的一致性。

------------------------------------------------------------------------

# 3. North Star

Numi Workflow 的最终目标：

> 帮助人类成为能够驾驭长期 Agent 协作的新型工程师。

未来软件开发能力不仅来自：

-   更强的模型；
-   更强的 Agent Harness；
-   更强的自动化。

也来自：

-   人类定义目标的能力；
-   人类表达约束的能力；
-   人类管理复杂性的能力；
-   人类与 Agent 协作的能力。

------------------------------------------------------------------------

# 4. Human-Agent Co-evolution

Numi 不认为未来模式是：

    Human 使用 Agent

而是：

    Human + Agent 协同进化

随着：

-   基础模型能力提升；
-   Agent Harness 能力提升；
-   用户经验提升；
-   项目复杂度变化；

协作模式应该动态调整。

------------------------------------------------------------------------

# 5. Numi 解决的问题

## 5.1 意图转换

人类拥有：

-   业务目标；
-   领域经验；
-   产品判断；
-   风险偏好。

Agent 需要：

-   明确目标；
-   执行边界；
-   验收标准。

Numi 负责降低：

    Human Intent

            ↓

    Agent Execution

    之间的信息损失。

------------------------------------------------------------------------

## 5.2 长周期协作

复杂项目不是一次对话完成。

需要保持：

-   项目背景；
-   历史决策；
-   当前状态；
-   未完成事项。

------------------------------------------------------------------------

## 5.3 决策一致性

Agent 可以快速生成方案。

但长期项目需要知道：

-   为什么这样设计；
-   哪些方案被拒绝；
-   哪些约束不可改变。

------------------------------------------------------------------------

# 6. Numi 与 Coding Agent 的关系

Numi 不替代：

-   Codex；
-   Claude Code；
-   Gemini CLI；
-   其它 Coding Agent。

Coding Agent 负责：

-   编码；
-   调试；
-   测试；
-   工具执行。

------------------------------------------------------------------------

# 7. Numi 与成熟 Workflow 的关系

Numi 不重复建设：

-   TDD；
-   Code Review；
-   Worktree；
-   Debugging；
-   Implementation Workflow。

优先复用：

-   Superpowers；
-   Matt Pocock Skills；
-   其它成熟工程实践。

关系：

    numi-workflow

    目标定义
    决策边界
    Feature 生命周期

            ↓

    Superpowers / Matt Skills

    工程执行纪律

            ↓

    Coding Agent

    代码实现

------------------------------------------------------------------------

# 8. 核心 Skill 重新定位

## project-discovery

不是简单分析项目。

而是：

> 建立 Human 与 Agent 对项目的共享世界模型。

负责：

-   项目背景；
-   长期依据；
-   架构约束；
-   领域知识。

------------------------------------------------------------------------

## feature-shape

这是 numi 的核心能力之一。

负责：

    模糊目标

    ↓

    Feature 基线

    ↓

    范围
    约束
    风险
    决策边界
    验收标准

目标：

让 Agent 在开始执行前理解：

-   为什么做；
-   做什么；
-   不做什么。

------------------------------------------------------------------------

## feature-slice

不是简单生成 ticket。

核心目标：

> 将 Feature 转换为 Agent 可以可靠执行的工作单元。

重点：

-   边界清晰；
-   可验证；
-   fresh session 可接手；
-   不依赖隐藏上下文。

------------------------------------------------------------------------

# 9. Feature-deliver 重新定位

## 原风险

Feature-deliver 容易演化为：

-   Agent 调度器；
-   Workflow Engine；
-   自动执行平台。

这不是 numi 的目标。

------------------------------------------------------------------------

## 新定位

Feature-deliver：

> 管理 Feature 从目标确认到交付完成的状态、证据和协作边界。

负责：

-   当前状态；
-   完成证据；
-   验收状态；
-   异常升级。

不负责：

-   Agent 调度；
-   代码执行；
-   工具调用。

------------------------------------------------------------------------

# 10. Codex-handoff 与 Numi 的关系

Handoff 和 Numi 是互补关系。

    Human

     ↓

    numi-workflow

    目标
    决策
    Feature 状态

     ↓

    codex-handoff

    上下文转移

     ↓

    Coding Agent

    执行

codex-handoff 解决：

> Agent 如何跨 session 延续工作。

numi 解决：

> Agent 为什么继续工作，以及继续工作的目标和边界是什么。

------------------------------------------------------------------------

# 11. Capability Registry 的定位

Capability Registry 保留作为架构抽象。

用途：

描述：

    Workflow Capability

            ↓

    Provider

            ↓

    Execution Backend

但 v0.7 不实现：

-   自动发现；
-   动态调度；
-   Agent Marketplace。

原因：

当前没有真实需求验证。

------------------------------------------------------------------------

# 12. 明确不做

v0.7 不建设：

## Agent Runtime

不负责：

-   调度 Agent；
-   管理 Agent 生命周期；
-   替代 Codex。

------------------------------------------------------------------------

## Workflow Engine

不追求：

-   固定流程；
-   所有任务强制经过同样步骤。

------------------------------------------------------------------------

## 重复已有能力

已有成熟能力：

优先复用。

# 14. 后续演进原则

任何新增能力必须回答：

1.  是否来自真实 Human-Agent 协作痛点？
2.  是否提升人与 Agent 的协作质量？
3.  是否已有成熟方案可以复用？
4.  是否增加不必要复杂度？

------------------------------------------------------------------------

# 15. 最终原则

Numi Workflow 的价值不是让 Agent 替代人。

而是：

> 让人类和 Agent
> 发挥各自优势，通过持续学习和协作能力提升，以更高效率、更高质量地完成复杂目标。
