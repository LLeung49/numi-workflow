# 项目基线梳理

目标：

1. **这个项目长期认定什么？**
2. **以后去哪里找？**
3. 对复杂已有项目：**哪些当前代码事实已经验证过，不需要下一次重新全库扫描？**

完成后停在 Gate A（项目基线评审）。

## 先分清两种资料

### 规范性项目基线：规定“应该是什么”

包括：

- 项目定位与范围；
- 需求；
- 架构；
- 工程规范；
- 领域术语；
- ADR。

### 现状事实记录：描述“现在是什么”

仅复杂已有项目按需创建。

例如：

- 当前数据流从哪里进入；
- 哪些模块正在调用某个旧接口；
- 当前没有某种发布层；
- 某个字段目前有哪些隐性消费者。

现状事实有新证据即可勘误；规范性决定不能因为代码现状不同就被自动覆盖。

## 1. 先复用已有资料

- 不默认扫描整个仓库或全部聊天历史。
- 已有项目先找项目入口、架构文档、工程规则、已有审计 / 盘点和 ADR。
- 如果已有一份可信的现状盘点，先复用，再按当前需要增量核实。
- 不因为旧文档“可能过时”就重新全库审计。
- README、代码、聊天、review 报告都可以提供线索，但都不能自动升级成已批准要求。

把输入区分为：

1. 可核实事实；
2. 用户已明确决定；
3. 待验证假设；
4. 外部 / AI 审查主张。

第 4 类必须复核后才能进入事实记录或开发任务。

## 2. 只澄清真正影响后续开发的问题

只追问会改变：

- 范围 / 明确不做；
- 用户可观察行为；
- 公共接口 / 架构边界；
- 验收标准。

领域词确认后写 `CONTEXT.md`；它只做领域术语表。

重要、难逆转、有真实取舍的决定才创建 ADR。

重要 ADR 建议同时写：

- 不变量；
- 明确不做。

## 3. 判断是否需要“现状事实记录”

只有以下情况之一明显成立时才建议创建：

- 已有大型 / 遗留代码库；
- 当前准备做重构 / 架构治理；
- 文档和代码长期漂移；
- 功能设计高度依赖“当前到底怎么实现”；
- 后续多会话会反复查询同一批代码事实。

否则不要创建。

默认位置：

```text
docs/current-state/<topic>.md
```

推荐每条事实记录：

```text
事实编号
结论
验证版本
证据：path + symbol + command/test
状态
影响范围
```

不要只依赖行号。

## 4. 勘误而不是重复审计

如果已有现状事实与当前代码不符：

1. 核实当前 HEAD；
2. 修正原事实；
3. 增加勘误记录；
4. 标明新证据；
5. 标明影响哪些 ADR / 功能规格 / 开发任务。

如果事实修正会推翻已批准方向，列为 Gate A / B 复审事项。

## 5. 项目资料索引

没有既有入口时使用根目录 `PROJECT.md`。

推荐：

```markdown
# Project

状态: 待评审
版本: <commit / revision>

## 项目定位
...

## 长期资料

| 职责 | 来源 | 适用范围 | 版本 / 状态 |
|---|---|---|---|
| 需求 | docs/requirements.md | whole project | ... |
| 架构 | docs/architecture.md | whole project | ... |
| 工程规范 | AGENTS.md | repo | ... |
| 领域术语 | CONTEXT.md | project | ... |
| ADR | docs/adr/ | scoped | per ADR |
| 现状事实 | docs/current-state/... | scoped | verified at commit ... |

## Gate A 项目基线评审
批准记录: ...
```

不适用的职责不创建占位文件。

## 6. Gate A 自查

标记“待评审”前确认：

- 所有适用规范性职责有可追溯来源；
- 关键范围 / 架构 / 验收问题已经解决或明确列出；
- 项目资料索引可解析；
- 没把代码现状、调研结论或 review 主张冒充成已批准要求；
- `CONTEXT.md` 仍是纯术语表；
- 需求与工程规范没有混层；
- 如果建立了现状事实记录，它有明确验证版本和证据；
- 如果修正了现状事实，受影响决定已列出来。

Git 项目批准后优先用 commit / tag 作为版本锚点。

结束时输出：

```text
Gate A 项目基线评审

项目资料索引:
- ...

规范性项目基线:
- ...

现状事实记录:
- 无 / <path + verified revision>

本次新增或勘误的事实:
- ...

仍待确认:
- ...

建议重点看:
- ...
```

本 Skill 不生成业务代码、不自动 commit / push。完成后停在 Gate A。
