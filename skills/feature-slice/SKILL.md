# 任务拆解

目标：

> 把一个已经定义清楚的功能，拆成完全没有旧聊天记忆的新 Agent 也能独立完成并验收的开发任务。

完成后停在 Gate C（任务拆解评审）。

## 1. 先检查是否可以拆任务

读取：

- 完整功能规格；
- Gate B 批准记录；
- 功能依据清单；
- 拆任务需要的接口、代码和测试；
- 功能规格引用的相关现状事实记录。

确认：

1. Gate A / B 对当前版本有效；
2. 任务拆解准备状态 = 可开始；
3. 功能规格已经基于最新证据 / 决定重新计算 blocker，且“当前真正 blocker”为空；
4. 客观事实类当前 blocker 已经由证据关闭，不能留给开发 Agent 猜；
5. 功能 / 架构 / 风险决策类当前 blocker 已经得到对应确认，或已有明确批准的保守处理 / 范围收缩；
6. 条件性 blocker 可以保留，但本次任务拆解不得隐式激活它们；
7. 引用的现状事实没有已知失效；
8. 当前没有新的架构或产品决定需要补。

否则停止正式任务拆解。

如果规格里仍有“实现细节”类未决项，可以在开发任务中落成局部选择；但任务不能改变已经确认的功能行为、公共接口或验收标准。

如果功能规格里存在条件性 blocker，拆任务前逐一检查它的激活条件。例如：某 route 只有“未来启用自动补源”时才需要额外事实，那么当前任务不得顺手接入该 route。任何任务一旦要激活条件性 blocker，停止拆解并回 `$feature-shape` 做定向核实 / Gate B 复审。

## 2. 按端到端结果拆，不按技术层拆

原则：

- 先打通最小可运行路径；
- 一张任务一个主要结果；
- 每张任务完成时就能独立验收；
- 测试和实现放同一张任务；
- 任务大小按复杂度、耦合和上下文判断；
- 不为了“端到端”虚构不存在的 UI；
- 新产品 / 架构决定退回 Gate A / B；
- 大范围机械重构采用“扩展 → 分批迁移 → 收缩”。

```markdown
## 修改范围

- ...

## 不要顺手做
- ...

## 验收标准
- ...

## 验证方式
- <真实可执行命令 / 人工检查>

## 新会话接手检查

```

### 执行开始后追加

```markdown
## 开发中新发现

- <发现>
  - 证据:
  - 是否阻塞当前任务:
  - 初步分类:
```

开发中新发现先记录，不自动解决。

任务结束前归类：

- 当前任务遗漏；
- 功能定义变化；
- 架构变化；
- 独立技术债；
- 现状事实勘误；
- 无需处理。

### 按需字段

```text
跨任务输入 / 输出
风险与回退
执行进度
执行建议（机械执行 / 常规开发 / 高判断）
```

## 4. 自包含的边界

开发任务应该自包含：

- 目标；
- 当前任务所需的关键事实；
- 精确代码 / 测试位置；
- 验收标准；
- 验证命令；
- 护栏。

但不要复制：

- 整份需求；
- 整份架构；
- 整份 ADR；
- 完整项目历史。

原则：

> **执行信息自包含，长期知识通过版本化引用复用。**

## 5. 新会话接手检查

### 第一层：所有任务自检

只依据“开发任务 + 任务上下文清单”，回答：

1. 要交付什么、不做什么？
2. 当前哪些事实已经验证？
3. 哪些项目决定已锁定？
4. 相关接口、测试边界和前置任务在哪里？
5. 怎样证明验收标准满足？
6. 功能规格里有哪些实现细节允许在本任务内决定，哪些事项已经明确锁定？
7. 哪些邻近事情明确不要顺手做？
8. 发现新的事实不确定性或功能 / 架构决策时，应该记录在哪、何时升级？
9. 当前任务是否会触发功能规格里的任何条件性 blocker？如果会，为什么它已经在 Gate B 被关闭？

### 第二层：关键任务真实新会话验证

优先：

- 第一张最小可运行路径任务；
- 高风险任务；
- 修改公共接口 / 架构边界的任务；
- 后续会复制其模式的任务；
- 自检仍有疑问的任务。

## 6. 校验任务依赖图

检查：

- 无循环依赖；
- 所有前置任务存在；
- 跨任务产物有明确生产者；
- 每个 AC 有责任任务和证据路径；
- 没有重复实现；
- 没有自行发明产品 / 架构决定；
- 没有通过“顺手支持一个新 route / 模式 / 能力”激活尚未核实的条件性 blocker；
- 共享文件 / schema / 接口的修改冲突已标注；
- 每张任务完成前序后可独立验收。

## Gate C：任务拆解评审

请用户重点看：

- 任务粒度；
- 第一张是否尽快打通最小可运行路径；
- 依赖是否真实；
- 是否出现横向分层任务；
- 哪些任务可以并行；
- 哪些任务要做真实新会话验证；
- “不要顺手做”是否覆盖最容易膨胀的邻近工作；
- 是否有任务隐式扩大已批准 route / 能力范围、激活条件性 blocker；
- 开发中新发现如何回写。

结束时输出：

```text
Gate C 任务拆解评审

开发任务:
- ...

最小可运行路径:
- ...

关键依赖链:
- ...

可并行候选:
- ...

新会话接手检查:
- ...

任务级护栏:
- ...

建议先执行:
- TICKET-...
```

本 Skill 不自动实现、不 commit / push。
