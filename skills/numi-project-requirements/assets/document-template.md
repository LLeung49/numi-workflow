## 4. 核心用户故事 (Core User Stories)

> 选取 4~6 个端到端故事，每个故事必须包含**明确、可判定的验收标准**。

### US-1：[故事名称：如核心主流程提交/执行]
作为 [目标角色]，我希望 [执行何种动作]，以便 [达成何种业务目标]。

**验收标准**：
- [标准 1：例如输入参数强类型校验，核心约束非法时友好拦截]；
- [标准 2：例如单条数据大小/规格上限拦截，超时控制]；
- [标准 3：例如只有成功落入持久化介质/提交状态后才返回成功响应，返回全局唯一 ID 与初始状态]；
- [标准 4：例如校验失败或持久化失败时，保证原子性，严禁脏数据残留]。

### US-2：[故事名称：如查询与状态跟踪]
作为 [目标角色]，我希望 [通过唯一 ID 查询状态]，以便 [诊断业务进度]。

**状态集合定义**：
- `PENDING`：[等待处理]
- `PROCESSING`：[正在处理/流转中]
- `SUCCESS`：[处理成功终态]
- `FAILED`：[失败且重试耗尽终态]
- `CANCELLED`：[未处理前主动取消终态]

**验收标准**：
- 查询至少返回唯一 ID、状态、创建时间、更新时间、重试/流转次数和最近错误；不得泄露敏感密钥。

### US-3：[故事名称：如主动干预与取消/回滚]
作为 [目标角色]，我希望 [取消/中止处于等待态或流转态的业务操作]，以便 [阻止无效处理或挽回损失]。

**验收标准**：
- 仅允许处于可取消前置状态的数据执行取消；已终态或不可撤销状态的操作不得被误判为首次成功；
- 干预动作具备幂等性与状态变更审计记录。

### US-4：[故事名称：如可靠执行与重试/异常兜底]
作为 [目标角色]，我希望 [在触发或流转时可靠执行，遇到瞬时故障时自动退避重试或触发降级策略]。

**验收标准**：
- 业务触发时间或时延精度控制在指定范围（例如 ±1 秒或特定 SLA）；
- 成功响应判定条件、可重试与不可重试错误分类明确；
- 最多重试 N 次，采用合理的重试策略（如指数退避加抖动），重试耗尽落入失败终态并发出告警。

## 5. 接口需求与字段约束大表

### 5.1 业务接口操作集
| 操作名称 | 请求语义 | 期望返回 | 幂等要求 |

| **[核心创建/提交操作，如 Submit/Create]** | 创建/提交数据 | 全局唯一 ID + 初始状态 | 基于业务唯一键幂等 |

## 6. 可靠性与一致性需求

### 6.1 数据事实与权威来源 (Data Truth)
- 已成功响应给客户端的数据，必须已经落入权威持久化介质或已提交状态；
- 内存结构只是临时调度与加速视图，系统崩溃重启必须能完全从持久化介质重建；
- 避免单点倾斜、并发争用与大对象瓶颈，数据采用合理的分片、事务隔离或独立实体存储。

### 6.2 故障语义与一致性承诺 (Fault Semantics)
- 根据项目业务场景明确一致性与容错语义承诺（例如：分布式事务/两阶段提交、或最终一致性与至少一次 (At-least-once)、或单机强一致 ACID）；
- 系统优先保障**数据不破坏、不丢失**；在瞬时故障或切换窗口内若有重复投递/重试，下游必须基于全局唯一 ID 具备幂等处理能力；
- 明确系统在网络分区、进程崩溃、存储宕机等极端情况下的行为边界（CP/AP 选择或熔断降级策略）。

## 9. 工程治理与质量需求

研发过程遵循工业级工程规范：
- **规格先行**：每个功能切片必须先有可执行规格，再编写代码；
- **人机共创与分工**：AI 负责高质量代码与测试实现，人类把关需求边界、架构审查与合并决策；
- **受保护红线**：根级 Harness、公共契约与不变量测试不可由开发 Agent 擅自放宽；
- **问题回填机制**：遇到缺陷优先回填修复规格与测试，再从干净状态重新验证，不在生成物上无限修补。

## 10. 最终系统级验收场景 (Final Acceptance Scenarios)

### 10.1 基础正向闭环
启动服务与依赖组件，提交标准数据，查询状态为初始态；到达业务完成条件后成功流转交付，状态变为成功终态。

### 10.2 重启自愈恢复
提交未终态数据，强杀服务进程；重启服务后，系统从持久化介质完全自愈重建，业务数据如期流转，一条不丢。

### 10.3 故障注入与异常自愈演练 (Fault Injection / Resilience)
在核心处理或并发流转中注入模拟故障（如强杀核心节点、依赖组件瞬时断开等）：备份机制或自愈逻辑在规定时间内感知并成功接管/重试恢复，数据全量闭环完成，日志留下完整切换与审计证据。

### 10.4 质量门禁与防作弊验证
构建、代码规范、类型检查、单元测试、集成测试全绿。故意注入错误测试用例时，CI 门禁必须 100% 拦截。
